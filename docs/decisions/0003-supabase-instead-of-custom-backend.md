# ADR-0003 — Supabase вместо собствен бекенд

- **Статус:** прието
- **Дата:** 2026-09-06

## Контекст

Втората версия има нужда от профили за учители, съхранение на резултати и
правила кой какво вижда. Проектът се поддържа от един човек и трябва да работи
в училище без системен администратор.

## Решение

Supabase: PostgreSQL с Row Level Security, вграден Auth (email за учители,
анонимни сесии за деца), достъп от браузъра. Няма собствен сървър.

Правилата за достъп живеят **в базата** — като RLS политики и функции със
`security definer`, а не в React кода. Браузърът не е място за проверка на
права.

## Последици

- Няма сървър за поддръжка, обновяване или сметки за хостинг.
- Фронтендът е статичен → публикува се на GitHub Pages безплатно.
- Логиката е на два езика (JavaScript и PL/pgSQL). Това е цена, платена
  съзнателно.
- Зависимост от един доставчик. Понеже отдолу е обикновен PostgreSQL,
  преместването е възможно.

## Отхвърлени алтернативи

- **Node/Express + собствена база.** Сървър, който в училището няма кой да
  поддържа.
- **Firebase.** Данните напускат ЕС по подразбиране — лош избор при работа с
  деца, дори когато не съхраняваме лични данни.
