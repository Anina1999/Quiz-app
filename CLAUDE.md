# CLAUDE.md

Указания за Claude Code при работа по този проект. Прочети този файл преди
първата промяна в кода.

## Какво е приложението

Образователен инструмент с тестове за ученици от **I до IV клас (6–10 години)**,
предназначен за употреба **в класната стая** — на училищен таблет, лаптоп или
интерактивна дъска. Учителят създава тестовете, децата ги решават, резултатите
и напредъкът се събират автоматично.

Потребителите са **малки деца**. Това не е стилистична бележка, а техническо
изискване: те четат бавно, натискат неточно, объркват се от плътен екран и се
разстройват от рязка отрицателна обратна връзка.

## Тех стек

- **React 19 + Vite 7**, React Router 7 (`HashRouter`)
- **Supabase** — PostgreSQL, Row Level Security, Auth (email за учители,
  анонимни сесии за деца)
- Деплой: GitHub Actions → GitHub Pages
- Само 4 продукционни зависимости. Дръж ги толкова.

## Структура

```
src/
  api/          заявките към базата, групирани по тема — страниците не викат supabase пряко
  components/   споделен UI (Alert, Field, Badge, ProgressBar…)
  game/         логиката на теста (useQuizGame) отделно от изгледа
  hooks/        useAsync, useFeedback
  lib/          supabase клиент, сесия на учител, сесия на ученик, звуци, константи
  pages/        по един файл на екран
supabase/
  migrations/   схема · RLS · SQL функции · права
  tools/        SQL за проверка, пуска се ръчно в SQL Editor
scripts/        smoke-test.mjs · bundle-sql.mjs
docs/           работната документация (виж най-долу)
legacy/         оригиналната версия с ванилен JavaScript — НЕ се променя
```

## Твърди правила

Нарушаването на което и да е от тях чупи основно решение в проекта. Ако смяташ,
че някое трябва да отпадне, първо го обсъди — не го заобикаляй.

1. **Никакви лични данни на деца в базата.** Учениците се идентифицират само с
   псевдоним и по избор номер в дневника. Не добавяй колони за име, фамилия,
   email, дата на раждане или снимка на дете. Виж [ADR-0001](docs/decisions/0001-no-child-personal-data.md).
2. **Верните отговори никога не стигат до браузъра на детето.** Оценяването е в
   `submit_answer()` в базата. Не добавяй `is_correct` в нищо, което
   `start_attempt()` връща. Виж [ADR-0002](docs/decisions/0002-grading-in-the-database.md).
3. **Никакви външни шрифтове, CDN или тракери.** От браузъра на дете не тръгва
   заявка към трета страна. Виж [ADR-0005](docs/decisions/0005-no-third-party-requests.md).
4. **Миграциите се добавят, не се пренаписват.** Файловете в
   `supabase/migrations/` вече са пуснати. Нова промяна = нов файл с по-късна
   времева отметка.
5. **Списъкът с предмети в [src/lib/constants.js](src/lib/constants.js) трябва да
   съвпада ТОЧНО с `CHECK` ограничението на `quizzes.subject`.** Нов предмет =
   промяна и на двете места, с миграция.
6. **Достъпността не се търгува.** Цели за докосване ≥ 56px, видим фокус от
   клавиатура, вярно/грешно се показва с икона И текст, не само с цвят,
   `prefers-reduced-motion` се уважава.
7. **Не пипай `legacy/`.** Това е запазената първа версия.
8. **Не комитвай** `dist/`, `supabase/dist/`, `.env.local`.

## Език

- **Целият интерфейс е на български.** Включително съобщенията за грешка —
  учител и дете трябва да ги разберат.
- **Коментарите в кода и в миграциите са на български.** Обясняват *защо*, не
  *какво*. Спазвай съществуващия тон: обяснява се решението и какво е било
  сгрешено преди него.
- **Съобщенията на комитите са на английски**, в повелително наклонение:
  `Add the student side and the quiz itself`.

## Стил на кода

- 4 интервала, единични кавички, точка и запетая.
- Функционални компоненти, hooks. Без класови компоненти.
- Страниците **не викат `supabase` пряко** — минават през `src/api/`.
- Един екран = един файл в `src/pages/`.
- Повтарящ се UI отива в `src/components/ui.jsx`, а не се копира.
- CSS е един файл с ясни секции и CSS променливи в `:root`. Без CSS-in-JS,
  без Tailwind.

## Команди

| Команда | Какво прави |
|---|---|
| `npm run dev` | сървър за разработка |
| `npm run build` | производствен билд |
| `npm run db:push` | пуска миграциите към свързания проект |
| `npm run db:bundle` | слепва миграциите в един SQL файл |
| `npm run test:smoke` | 130 проверки срещу локална Supabase (`npx supabase start` първо) |

След промяна в SQL: пусни `npm run test:smoke`. Той проверява и защитата — че
дете не може да прочете верните отговори или чужди резултати.

## Работен процес

1. Преди работа прочети [docs/plan.md](docs/plan.md) и [docs/phases.md](docs/phases.md)
   — какво е приоритетът в момента.
2. Взето архитектурно решение → нов файл в [docs/decisions/](docs/decisions/) и
   ред в [docs/decisions.md](docs/decisions.md).
3. Сгрешено и поправено нещо, чиято причина не е очевидна → ред в
   [docs/error-log.md](docs/error-log.md). Този файл е спестено време за
   следващия път, не изповед.
4. Възникнал въпрос, на който не можеш да отговориш сам → [docs/open-questions.md](docs/open-questions.md).
5. В края на сесията → запис в [docs/sessions-log.md](docs/sessions-log.md).
